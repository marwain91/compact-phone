  settings forwarders collapsed onto SettingsController** (exposed as
  `PhoneController.settings`; ~22 pass-through properties + signals + the
  re-emit wiring removed; the one non-pure forwarder's Sentry side effect moved

## SUMMARY

Two rounds run (broad scan → deep dive) across five read-only specialists, then
safe fixes applied behind the full test gate.

- **Security:** 1 Critical, 0 High (two broad-scan "High"s were refuted on deep dive — see below), 3 Low.
- **Architecture:** 1 safe-fix-able pass-through cleanup, 6 structural proposals.
- **Cost & performance:** 1 high-ratio N+1, several model/DB micro-costs.
- **Data-layer:** 1 latent migration-counter trap, missing indexes, WAL not enabled.
- **Cleanup:** 2 true safe-fixes (applied), 4 proposals.

### Top 5 highest-impact items
1. **[Critical, security]** TLS server-cert verification never actually happens for TLS SIP accounts, even with `allowUntrustedCert=false` (the default) — MITM exposes SIP digest credentials.
2. **[High, data/perf]** `ConversationsModel::refresh` runs N+1 queries (one `listByPeer(p,1000)` per peer) on every inbound/outbound message.
3. **[Med, data correctness]** Migration counter trap: `kLatestVersion=7` vs `kSqlMigrationCount=5`; versions 6 & 7 silently call `migrate004` with no compile-time guard.
4. **[High, architecture]** `PhoneController` is a 1184-line god object owning 25 subsystems and re-exporting their entire API as pass-through getters/setters.
5. **[Low→Med, security]** File keychain encrypts with a hardcoded in-binary master secret + plaintext salt; on **macOS it is the primary store** (migrates secrets *out* of the OS Keychain), a security downgrade.

## PROPOSALS (report-only; triage over time)

### Security
- **[Critical] TLS cert verification does not bind for TLS accounts** — `src/core/SipEngine.cpp:60-74`, `src/core/AccountsManager.cpp:607-626`. `SipEngine::start()` creates the process's first/only TLS transport with `verifyServer=false`; that permissive transport governs the handshake regardless of the per-account `verifyServer=!allowUntrustedCert`. The code comment admits per-account verify "becomes functional in v0.3", contradicting `AccountsManager`'s present-tense use. The only TLS integration test runs with `allowUntrustedCert=true`, so the secure path is never exercised. **Secure version:** fail closed — default the shared transport to `verifyServer=true`, relax only for accounts that opt into `allowUntrustedCert`, route each account over a transport carrying its own verify policy, and add an integration test asserting `allowUntrustedCert=false` against a self-signed server *fails* to register.
- **[Low] File keychain hardcoded master secret** — `src/core/platform/Keychain_file.cpp:29,38-62`. `kMasterSecret="compactphone-v0.2-master"` is the only IKM into HKDF; salt is stored beside the ciphertext. On macOS, `Keychain_factory.cpp:38-65` migrates secrets *out* of Security.framework into this weaker file store. **Secure version:** seal a per-install random key in the OS keystore (Keychain/DPAPI/libsecret) and use it as IKM; on macOS reconsider migrating out of Security.framework. At minimum document the downgrade. (Remote break needs local file read; mitigated by FileVault/profile protection.)
- **[Low] UpdateChecker accepts `http://` and does not verify signatures** — `src/core/UpdateChecker.cpp:28-36,113-115`. `isUsableHttpUrl` permits `http`; the enclosure host is not pinned. **Secure version (safe-fix-able):** require `https` for feed + enclosure and pin the host to `github.com`/`objects.githubusercontent.com`. (Signature verification = larger proposal.) *Not auto-applied — would change behaviour and likely needs `test_update_checker` fixture updates.*
- **[Low] Daktela access token in URL query string** — `src/core/provisioning/DaktelaProvider.cpp:97-118`. Token is also sent via `X-AUTH-TOKEN` header (lines 387/427), so the query param is redundant and removable; residual risk is server/proxy access-log exposure. **Note:** the broad-scan claim that the token reaches `exportDiagnostics` was **refuted** — the only logged URL (`onDiscoveryReply`, line 276) is `globalsettings.json` with no token. *Removal needs confirmation the provisioning server accepts header-only auth → proposal, not auto-applied.*
- **[Refuted] PJSIP wire logs leaking Authorization headers into diagnostics** — default log level is `info`; PJSIP level-4 dumps map to `spdlog::debug` and are filtered out before the export buffer. Exposure exists **only** if a user opts into debug/trace logging *and* exports. Optional hardening: redact `Authorization`/`Proxy-Authorization`/IM bodies in `SpdlogPjsipWriter::write`.

### Architecture
- **[high×med] `PhoneController` god object** — `src/core/PhoneController.{h,cpp}` (1184 lines, 25 `unique_ptr` subsystems, ~40 pass-through settings getters/setters). Make it a composition root that exposes the sub-controllers (`SettingsController`, `CallsController`, `AccountsController`) as QML singletons; QML binds them directly. Keeps only cross-cutting state (`notice`, quit, tray).
- **[high×med] Settings state/API triplicated** — `SettingsManager` (k/v) + `SettingsController` (typed cache) + `PhoneController` (forwarders). Collapse to: Manager = persistence, Controller = QML-facing surface; drop PhoneController's copy (folds into the above).
- **[high×med] Audio-device I/O inside a settings controller** — `src/core/SettingsController.cpp:80,248-266` calls pjsua2 `audDevManager()` directly. Move enumeration behind `SipEngine`; controller consumes a plain list.
- **[med×med] `SettingsPane.qml` (1059 lines) = six settings screens in one file** — split into per-tab components.
- **[med×med] `BootConfig.cpp` (682 lines) mixes CLI parse + JSON load + merge + secret resolution** — split into independently testable units.
- **[med×med] `CallManager.cpp` (871 lines) bundles lifecycle + recording + transfer-cleanup** — extract `CallRecorder` and `TransferTracker`.
- **[med×low] Provider sniffing in generic dialer UI** — `src/ui/qml/DialerPane.qml:99-104` does `label.indexOf("daktela")`. Surface a `providerId` role on the account model instead.

### Cost & performance
- **[high×low/med] `ConversationsModel::refresh` N+1** — `src/models/ConversationsModel.cpp:53-78`. Replace `peers()` + per-peer `listByPeer(p,1000)` with one window-function query returning `peer_uri, last body/direction/created_at_ms, unread_count`:
  ```sql
  SELECT peer_uri, body AS last_body, direction AS last_direction,
         created_at_ms AS last_created_at_ms, unread_count
  FROM (SELECT peer_uri, body, direction, created_at_ms,
               SUM(CASE WHEN direction='in' AND read=0 THEN 1 ELSE 0 END)
                 OVER (PARTITION BY peer_uri) AS unread_count,
               ROW_NUMBER() OVER (PARTITION BY peer_uri
                 ORDER BY created_at_ms DESC) AS rn
        FROM messages)
  WHERE rn = 1 ORDER BY last_created_at_ms DESC;
  ```
- **[high×med] Redundant `snapshot()` copies per call event** — `src/core/CallsController.cpp:36-60,224-244`. `findCallEntry`, `aggregateCallState`, and `ringing()` each re-`snapshot()` (full vector + per-call PJSIP `getInfo()`). Thread one snapshot through the handler; cache `m_ringing` from events.
- **[high×low] Per-key settings reads at startup** — `SettingsController` issues ~15 sequential `getOr()` calls, each a full prepare/step/finalize. Load all settings once with `SELECT key,value FROM app_settings` into a map.
- **[med×low] Model `beginResetModel` storm** — `Contacts/History/Messages/AccountsModel::refresh` tear down every QML delegate on each CRUD. Adopt the incremental-diff pattern already used (and deliberately kept) in `CallsModel`.
- **[med×low] Per-call 2s QML stats polling** — `src/ui/qml/ActiveCallView.qml:187-199`. Centralise in one C++ `QTimer` on `CallsController`, push via signal.

### Data-layer
- **[med, correctness] Migration counter trap** — `src/persistence/Database.cpp:103-106,231-235`. `kLatestVersion=7` vs `kSqlMigrationCount=5`; v6 & v7 both call `migrate004` (idempotent today via `addColumnIfMissing`, so no corruption — but a latent trap for the next migration author). **Fix sequence:** restructure dispatch to a `MigrationFn` function-pointer table so `version == index`, *then* the `static_assert(kLatestVersion == kSqlMigrationCount)` becomes valid. (The assert cannot be added as-is — it would fail to compile against the current divergence.)
- **[med, perf] Missing indexes** — no index on `contacts.sip_uri` (`findByUri` scan; no callers yet) and none on `messages(direction,read)` (`unreadCount()` scan, hot via `messagesChanged`). Add `CREATE INDEX IF NOT EXISTS` in a new migration — **blocked on fixing the counter trap first**.
- **[low, perf] WAL not enabled** — only `PRAGMA foreign_keys=ON` at open (`Database.cpp:207`). `journal_mode=WAL` + `synchronous=NORMAL` is the standard single-writer-desktop win. Idempotent, no migration. *Not auto-applied: changes durability/journal semantics + adds `-wal`/`-shm` sidecars → deserves a deliberate decision.*
- **[low] `schema_version` row accumulation** — `MAX(version)` read is correct today; switching to single-row upsert has a bootstrapping risk on installed DBs → leave as-is.

### Cleanup & quality
- **[med×low] Notice-timeout magic numbers** — `PhoneController.cpp` has **six** distinct toast durations (2500/3000/4000/5000/6000/8000) across ~13 call sites + header default. Introducing named constants needs a reviewed value→name mapping (not a blind rename), so: proposal.
- **[med×med] Duplicated `bindText`/`readText` helpers** — byte-identical anonymous-namespace copies in `HistoryManager.cpp` and `ContactsManager.cpp` (`MessagesManager` inlines its own). Consolidate into `persistence/` — needs a placement decision → proposal.
- **[med×low] Inconsistent null-DB guarding** — `MessagesManager` guards every method; `HistoryManager::append`/`ContactsManager::add` don't. Unifying turns a crash into a silent sentinel (behaviour change on the error path) and should be all-methods + tested → proposal.
- **[med×low] `catch(...)` swallow blocks** — several sites in `SipEngine`/`AccountsManager`/`CallManager`/`SettingsController` discard exceptions with no log line. Audit each: best-effort-teardown (keep) vs unlogged-failure (log it).
- **[low] `listByPeer(p,1000)` magic limit** — `ConversationsModel.cpp:59`. Single-use literal; naming it hides the over-fetch smell. Prefer fixing the query (see perf N+1) over naming the constant.
