### Top 5 by impact
1. **[High, security]** Silent auto-dial from an external `tel:`/`sip:` URI —
   `handleUri` both populates the dialer AND calls `dial()` → `makeCall`, placing
   a call with no confirmation. Toll-fraud / forced-connect vector.
2. **[High, architecture]** PhoneController is still a god object for the
   un-extracted subsystems (contacts/messages/lines/provisioning hold logic
   directly; calls/accounts are pure passthrough).
3. **[Med, security]** Externally-sourced SIP URI passed verbatim to PJSIP
   `makeCall` — injectable URI params/headers can alter INVITE routing.
4. **[Med, data]** `messages`/`watched_lines` lack the FK constraint
   `call_history` has → orphaned rows on account deletion.
5. **[Med, perf]** Six models do full `beginResetModel` on every CRUD; per-call
   stream-stats polled from a QML `Timer` hitting PJSIP locks.

## APPLIED SAFE FIXES (this branch)

- **sqlite helper consolidation + null-safety** — `AccountsManager` and
  `MessagesManager` now use `persistence::bindText`/`readText` instead of a
  private `bindText` copy and bare `reinterpret_cast<const char*>` reads.
  `readText` maps a NULL column to `""` rather than constructing a `std::string`
  from `nullptr` (UB). — tests: unit 213/213.
- **X-AUTH-TOKEN redirect policy** — `DaktelaProvider` sets
  `SameOriginRedirectPolicy` on the token-bearing requests so a cross-host
  redirect can't replay the token. — tests: green.
- **dead include removed** — `platform/Keychain_file.h` from `PhoneController.cpp`
  (keychain comes from `makeKeychain`; `FileKeychain` unreferenced). — tests: green.

## PROPOSALS (report-only; triage over time)

### Security
- **[High] Silent auto-dial from external URI** — `PhoneController.cpp:326-327`
  (`handleUri` calls `setDialerUri` AND `dial(target)`) → `CallsController::dial`
  → `CallManager::makeCall` issues the INVITE immediately. **Secure version:**
  populate the dialer and require an explicit Call press (or a "Call <target>?"
  confirm) for externally-delivered URIs; never auto-dial across a trust
  boundary. Add a test asserting an inbound URI does not reach `makeCall`.
- **[Med] Unvalidated SIP target into PJSIP** — `SipUri.cpp:46` returns a
  scheme-bearing input unchanged into `Call::makeCall`; injected `;params` /
  `?headers` reach PJSIP and can alter INVITE routing. Validate to `user@host`
  + an allowlisted `transport`, strip `?`-headers and control chars. (Fixing the
  auto-dial removes the main attacker path.)
- **[Low] Unbounded `readAll()`** — `UpdateChecker.cpp:150`,
  `DaktelaProvider.cpp` (×4): cap accepted body size and fail closed (e.g. 1 MiB
  for the appcast XML / Daktela JSON). Clean mechanical fix worth bundling.
- **[Low, known] FileKeychain master key beside ciphertext** (Linux residual);
  **[Low] Windows creds at `CRED_PERSIST_LOCAL_MACHINE`** scope — documented
  limitations, not regressions.

### Architecture
- **[high×med] Extend the controller pattern** — extract `ContactsController`,
  `MessagesController`, `LinesController`, `ProvisioningController` mirroring the
  Settings/Calls/Accounts ones; QML reaches them as `PhoneController.contacts.x`
  etc. PhoneController shrinks to a composition root. (`PhoneController.cpp` is
  922 lines — still the largest file.)
- **[high×med] Single composition root** — `PhoneController` and
  `headless_main.cpp` hand-build the same manager+controller graph twice; they
  will drift. Extract one `AppGraph`/`CoreContext` builder.
- **[low×low] Contacts model refresh threaded manually** — `PhoneController`
  calls `m_contactsModel->refresh()` at 4 sites while other models self-refresh
  off manager signals; folds into a `ContactsController`.
- **[med×low] Duplicated labeled-field QML** across AccountEditDialog (8),
  ContactEditDialog (3), ProviderSignInDialog (4) → one `components/AppTextField.qml`.
- **[med×med] Large untouched QML views** — AccountEditDialog (599),
  ActiveCallView (496), ProviderSignInDialog (490), DialerPane (488); move dial
  parsing in DialerPane into a tested C++ helper.

### Cost & performance
- **[high×med] Centralize stream-stats** — `ActiveCallView.qml` polls
  `streamStats` every 2s per call (PJSIP `getInfo`+`getStreamStat`, locks). Push
  from one C++ `QTimer` via a signal.
- **[high×med] `firstHeldCallId` snapshot in a QML binding** — `ActiveCallView`
  `mergeAction.visible` calls `PhoneController.firstHeldCallId` (full snapshot)
  on every binding re-eval; expose a cheap `hasHeldCall` bool. Also: route it
  through `CallsController` (it bypasses the controller — layering).
- **[med×med] `beginResetModel` storm** — Contacts/History/Messages/Accounts/
  Conversations/Lines models reset on every CRUD (CallsModel's incremental diff
  is the template).
- **[med×low] No prepared-statement reuse** — ~29 `sqlite3_prepare_v2` sites
  prepared per call; cache `sqlite3_stmt*` and `reset` on reuse.
- **[med×low] `unreadMessageCount` runs `COUNT(*)` per binding eval** — maintain
  an in-memory counter.

### Cleanup & quality
- **[med×low-med] Toast-timeout magic numbers** in `PhoneController` (2500–8000
  across ~14 sites) — introduce category constants (needs a value→intent map,
  so a reviewed change, not a blind rename).
- **[med×med] `catch(...)` swallow** sites (SipEngine/AccountsManager/CallManager/
  LinesManager/RingtonePlayer) — per-site triage: teardown-best-effort (keep) vs
  unlogged failure (log).

### Data-layer
- **[med] Missing FK constraints** — `messages.account_id` and
  `watched_lines.account_id` lack `REFERENCES accounts(id) ON DELETE CASCADE`
  (which `call_history` has) → orphaned rows on account delete. **Not a
  safe-fix:** with `foreign_keys=ON`, the manager tests that insert child rows
  without a parent account would start failing, so this needs the tests to seed
  an account first. Add the FK + update those tests together.
- **[low] Downgrade is a silent no-op** in the migration runner (`current >
  kLatestVersion` returns true with no log/guard) — harmless at v1, a trap once
  v2 ships. Add a guard log when the DB is newer than the binary.
- **[low] Dead `MessagesManager::peers()`** — superseded by
  `conversationSummaries()`, still in the public API; remove or mark deprecated.
- **[low] Unbounded `ContactsManager::list()`** / no `account_id` index — fine at
  current scale; revisit if a large directory import or per-account filter lands.
